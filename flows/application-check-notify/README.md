## 2. 貼り付け手順

1. PAD コンソールで［＋ 新しいフロー］を押し、フロー名に **申込状況チェック_通知付き** と入力して［作成］（同じ名前の UI 要素が無い新しいフローにする）。
2. [Main.txt](./Main.txt) を開き、**Ctrl＋A で全文をコピー**する（末尾の `# [ControlRepository][PowerAutomateDesktop]` の行と JSON の最後の `}` まで含める）。
3. PAD デザイナーの **Main** タブの空いている所をクリックし、**Ctrl＋V** で貼り付ける（UI 要素も自動登録される）。
4. ［UI 要素］ペインで、`LoginPage`・`ListPage`・`DetailPage` の3画面・計8要素があり、`detail-button` のセレクターに `%CurrentNo%` が残っていることを確かめる（資産4と同じ）。
5. 変数ペインの **`LoginPassword` を機密としてマーク**する。
   - 続けて、3つの「Web ページのリンクをクリック」（ログインボタン No.46・「詳細」No.80・「一覧へ戻る」No.96）を開き、［詳細］の「**物理的なクリックを送信**」が **オフ** になっていることを確かめる（今の版の設定。資産4の手順書では「物理クリックを送信」と表記。**オンになっていたらオフにして保存する**。[reference.md](./reference.md) の 7 の No.46・80・96）。
6. 貼り付け直後は、SharePoint・Teams のアクション（5つ）と、プレースホルダーの `<…>` を使う箇所でエラーが出る・保存できないことがある。**プレースホルダーのまま貼り付けて保存できるかは未確認**（最初の版は書式が違って「不明なアクション」になった）。次の「3.」で接続参照・サイトを選び直して 0 件にし、［保存］する。ステータス バーのアクション数は 229 の見込み（最初の版の貼り付けでは実機でも 229 と表示された）。
7. 保存できない・アクションが「不明」と表示される場合は、そのアクションを消し、[reference.md](./reference.md) の「6-2」の表どおりに手で配置する。

## 3. 貼り付けたあとの設定（人が PAD 上で行う。実値はどこにも書かない）

`Main.txt` のコネクタ 5 行は、実機の PAD が出力した書式（接続参照 ID・`ConnectorId` のパス・`@` 付きの入力）に合わせてあり、接続参照 ID・接続参照名・サイト・フォルダー・投稿先はプレースホルダー（`<…>`）のまま。**貼り付けただけで保存できるかは未確認。** 詳しい書式と、うまくいかないときの手順は [reference.md](./reference.md) の「6」。

再設定の方法は次のどちらか。

- **A. PAD 上でアクションを開いて選び直す（推奨）**：貼り付け後、コネクタの 5 つのアクションを順に開き、「接続」で作成済みの接続参照を選ぶ。SharePoint の 3 つはサイトを一覧から選ぶ。
- **B. 貼り付ける前に置換する**：コピーした `Main.txt` の `<SharePoint 接続参照ID>`・`<SharePoint 接続参照名>`・`<SharePoint 接続名>`・`<Teams 接続参照ID>`・`<Teams 接続参照名>`・`<Teams 接続名>`・`<サイト名> - <保存先サイト>`・`<保存先サイト>` を実値に置き換えてから貼り付ける（置換後は**コミットしない**）。

| # | 場所（`Main.txt` / アクション表の No.） | 設定すること |
|---|----------------------------------------|--------------|
| 1 | 接続参照（コネクタのアクション 5 つの「接続」） | 作成済みの SharePoint と Teams の接続参照を選ぶ（上の A または B） |
| 2 | 先頭の変数の設定 No.1 `SharePointSiteUrl` | 保存先サイトの URL（履歴ファイルのリンクの組み立てに使う）に置き換える |
| 3 | 先頭の変数の設定 No.2 `SharePointFolder` | 保存先フォルダー（ライブラリ名を含むパス）を**直接入力**する |
| 4 | SharePoint のアクション 3 つ（No.111・143・148）の「サイト」 | **ドロップダウンの一覧から**保存先サイトを選ぶ。フォルダー・ファイル名は変数のまま（入力済み） |
| 4b | No.111 の出力 | 出力 `GetFileContentByPathResponse` の格納先が `PreviousBinary` になっていることを確認する。**この変数が「応答」型でファイルの内容そのものではない可能性がある**（未確認。reference.md の 6-3 の C1。実行後に変数ペインで型を確認する） |

- 設定したあと、`Main.txt` の `<…>` が残っていないか PAD のアクション表示で確認する。**設定した値を `Main.txt` や docs に書き戻さない**（コミットしない）。

## 4. 実行手順（デモ当日の注意は資産4の README と同じ：実行中は操作しない）

> 1. **【必須】実行中（Edge が閉じるまで）は、マウス・キーボードを操作しない。** ほかのウィンドウを前に出す操作もしない。通知を出すアプリ（チャット・メール等）は閉じておく。
> 2. 今の版のクリックはマウス カーソルを動かさない（「物理的なクリックを送信」オフ）。実行中にマウス カーソルが動かなくても正常。**それでも上の 1 の【必須】は変わらない**。

1. `node mock/server.js` でモックを起動する（資産4と同じ）。
2. **場面の下準備**（人が行う。フローは SharePoint・モックのデモ操作エリアを触らない）：

   | 場面 | モックの件数 | SharePoint の `latest.csv` |
   |------|--------------|----------------------------|
   | 初回 | 初期20件 | **無い**状態にする（削除する） |
   | 新規あり | 初回の直後に、デモ操作エリアで［新規案件を追加］を2回押して22件 | 初回で保存された20件のまま |
   | 新規0件 | 22件のまま | 新規ありで保存された22件のまま |
   | 失敗 | 実行前に `node mock/server.js` を止める | 変えない |

   デモ当日（`docs/demo-script.md` 付加価値の準備 A1〜A5）は、A1 で「初期データに戻す」して20件にし、A2 でこのフローを1回実行する。`latest.csv` が既にあれば「新規案件はありません」、無ければ「初回実行のため…」が投稿される。
3. PAD で「申込状況チェック_通知付き」を［実行］する。Edge が閉じるまで操作しない。所要時間は資産4と同程度＋保存・投稿（実機は未計測）。
4. 結果の確認：
   - ローカル：ドキュメント フォルダの `申込状況チェック_デモ`（`申込状況_YYYYMMDD_HHMM.csv`・`latest.csv`・`previous.csv`）。失敗した実行では今回分は作られない

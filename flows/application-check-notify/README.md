## 概要

- フロー名：**申込状況チェック_通知付き**（資産5。`docs/flow.md` 0）
- **位置づけ：付加価値（保留）。デモ本編で使う正は資産4（`flows/application-check/`、申込状況チェック_デモ）で、この資産5ではない。** 資産4は書き換えていない。この資産5は資産4の別資産で、資産4のファイルを読み込んで動く形ではない（`Main.txt` 単体で貼り付けられる）

## 2. 貼り付け手順

1. PAD コンソールで［＋ 新しいフロー］を押し、フロー名に **申込状況チェック_通知付き** と入力して［作成］（同じ名前の UI 要素が無い新しいフローにする）。
2. [Main.txt](./Main.txt) を開き、**Ctrl＋A で全文をコピー**する（末尾の `# [ControlRepository][PowerAutomateDesktop]` の行と JSON の最後の `}` まで含める）。
3. PAD デザイナーの **Main** タブの空いている所をクリックし、**Ctrl＋V** で貼り付ける（UI 要素も自動登録される）。
4. ［UI 要素］ペインで、`LoginPage`・`ListPage`・`DetailPage` の3画面・計8要素があり、`detail-button` のセレクターに `%CurrentNo%` が残っていることを確かめる（資産4と同じ）。
5. 変数ペインの **`LoginPassword` を機密としてマーク**する。
6. 貼り付け直後は、SharePoint・Teams のアクション（5つ）と、プレースホルダーの `<…>` を使う箇所でエラー ペインに赤いエラーが出ることがある。次の「3.」で設定して 0 件にし、［保存］する。ステータス バーのアクション数は 229 の見込み（構文解析器で数えた数。実機は未確認）。
7. SharePoint・Teams のアクションが貼り付けで受け付けられない場合は、そのアクションを消し、[reference.md](./reference.md) の「6. コネクタのアクションの設定値」の表どおりに手で配置する。

## 3. 貼り付けたあとの設定（人が PAD 上で行う。実値はどこにも書かない）

| # | 場所（`Main.txt` / アクション表の No.） | 設定すること |
|---|----------------------------------------|--------------|
| 1 | 接続参照 | 作成済みの SharePoint と Teams の接続参照が使えることを確認する（コネクタのアクション5つの「接続」） |
| 2 | 先頭の変数の設定 No.1 `SharePointSiteUrl` | 保存先サイトの URL（履歴ファイルのリンクの組み立てに使う）に置き換える |
| 3 | 先頭の変数の設定 No.2 `SharePointFolder` | 保存先フォルダー（ライブラリ名を含むパス）を**直接入力**する |
| 4 | SharePoint のアクション3つ（No.111・143・148）の「サイト」 | **ドロップダウンの一覧から**保存先サイトを選ぶ。フォルダー・ファイル名は変数のまま（入力済み） |
| 4b | SharePoint のアクション No.111（前回の `latest.csv` の取得）の**出力** | 出力（ファイルの内容）の変数名を **`PreviousBinary`** にする（構文解析器は、コネクタのアクションの出力を書き戻さないため、貼り付けでは引き継がれない可能性がある）。これが無いと、前回があっても「取得できなかった」と判定される |

| 6 | Teams のアクション2つ（正常時 No.171・失敗通知 No.182）の「投稿先」 | 投稿者（Flow ボット）・投稿先（Flow ボットとのチャット）・宛先を設定する。**2つとも同じ投稿先** |

- 設定したあと、`Main.txt` の `<…>` が残っていないか PAD のアクション表示で確認する。**設定した値を `Main.txt` や docs に書き戻さない**（コミットしない）。
- コネクタのアクションの入力名・出力は、PAD の画面で表示される名前に合わせて選び直す必要がある場合がある（照合できていないため。verification-log.md の 3）。

## 4. 実行手順（デモ当日の注意は資産4の README と同じ：実行中は操作しない）

1. `node mock/server.js` でモックを起動する（資産4と同じ）。
2. **場面の下準備**（人が行う。フローは SharePoint・モックのデモ操作エリアを触らない）：

   | 場面 | モックの件数 | SharePoint の `latest.csv` |
   |------|--------------|----------------------------|
   | 初回 | 初期20件 | **無い**状態にする（削除する） |
   | 新規あり | 初回の直後に、デモ操作エリアで［新規案件を追加］を2回押して22件 | 初回で保存された20件のまま |
   | 新規0件 | 22件のまま | 新規ありで保存された22件のまま |
   | 失敗 | 実行前に `node mock/server.js` を止める | 変えない |

   デモ当日（`docs/demo-script.md` 付加価値の準備 A1〜A5）は、A1 で「初期データに戻す」して20件にし、A2 でこのフローを1回実行する。`latest.csv` が既にあれば「新規案件はありません」、無ければ「初回実行のため…」が投稿される。
3. PAD で「申込状況チェック_通知付き」を［実行］する。Edge が閉じるまで操作しない。所要時間は資産4と同程度＋保存・投稿（実機は未計測）。
4. 結果の確認：
   - ローカル：ドキュメント フォルダの `申込状況チェック_デモ`（`申込状況_YYYYMMDD_HHMM.csv`・`latest.csv`・`previous.csv`）。失敗した実行では今回分は作られない
   - SharePoint：保存先に履歴ファイルと `latest.csv`
   - Teams：作成者の個人チャットに、下の投稿が1件

| 場面 | Teams の投稿 |
|------|--------------|
| 初回 | 初回実行のため、全 N 件を保存しました（比較する前回データがありません）＋履歴ファイルのリンク |
| 新規あり | 新規案件が N 件あります＋各案件（申込番号／お客さま名／申込種別／変更前 → 変更後の容量／ステータス）＋リンク |
| 新規0件 | 新規案件はありません（全 N 件を確認しました）＋リンク |
| 失敗 | 取得に失敗しました。手順◯◯で停止（リンクなし） |

文面の全文は [reference.md](./reference.md) の「5. Teams の投稿文」。

## 5. エラー早見表

資産4のエラー（E0〜E13）は資産4の README の「4. エラー早見表」と同じ。画面のメッセージ「申込状況チェック_デモ（エラーで停止しました）」も同じ。資産5では**それに加えて Teams に失敗通知**を投稿する。通知の「手順◯◯」は、画面のメッセージの先頭の部分と同じ。

| 止まった場所 | Teams の通知の手順名 | 人がすること |
|--------------|----------------------|--------------|
| E0〜E13（手順0〜4） | 手順0／1-1〜1-2／1-3〜1-4／1-4〜1-5／1-5／2-1／2-2／3-1／3-2／3-3〜3-4／3-3／3-4／3-5／4（対応表は reference.md の 4） | 資産4の README の表のとおり |
| **手順5-1**：前回の `latest.csv` の取得が、**ファイルが無い以外の理由**で失敗 | 手順5-1 | 接続・保存先・ネットワークを確認して再実行。初回扱いにはしない（`latest.csv` を壊さないため） |
| **手順5-3**：SharePoint への保存に失敗 | 手順5-3 | 接続・保存先を確認して再実行。履歴ファイルだけ保存済みで `latest.csv` が失敗した場合は、`latest.csv` が前回のまま（または無い）。再実行で上書きされる |
| **手順6**：正常時の Teams 投稿に失敗 | **通知しない**（画面のメッセージだけ） | CSV は SharePoint に保存済み。**このまま再実行すると新規0件になる**。デモでは `docs/demo-script.md` のリセット手順で戻す |
| 失敗通知の投稿自体が失敗 | — | 再投稿はしない。画面のメッセージだけが残る（メッセージ・Edge を閉じる処理は飛ばされない） |

- 正常時の投稿の失敗かどうかは、変数 `NotifyOnError`（手順6 に入るとき `NO` にする）で見分ける。
- 止まったら、メッセージを書き写すかスクリーンショットを撮ってから［OK］を押す（資産4と同じ）。自動の再実行はしない。

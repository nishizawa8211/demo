# 申込状況チェック_デモ — PAD フロー手順書（デモ当日用）

## 概要

- フロー名：**申込状況チェック_デモ**（`docs/flow.md` 0）
- 種類：Power Automate Desktop（PAD）のデスクトップフロー1本。クラウドフローは使わない
- 操作対象：モック「申込管理システム（デモ）」（`http://localhost:8080`）。一覧画面のデモ操作エリア（`#demo-tools`）は操作しない
- 範囲：`docs/flow.md` 手順0（初期化）→ 1（Edge 起動・ログイン）→ 2（申込番号の全件取得）→ 3（全件の詳細取得）→ 4（ローカルに CSV 出力）と、手順7 相当の「ブラウザーを閉じる」。SharePoint・Teams（手順5〜6）は含まない（別資産の保留。[reference.md](./reference.md) の 9）

**この手順書の位置づけ**：`Main.txt` は、この PC の PAD の構文解析器・アクション定義ファイルと照合済み（構文エラー 0・名前の不一致 0）。最新版は PAD の実機で、貼り付け・保存と、連続3回の正常終了（初期20件、各約2分弱、CSV は `dummy.json` と不一致 0）まで確認している。経緯と詳しい結果は [verification-log.md](./verification-log.md)。

## 1. 前提

| 項目 | 内容 |
|------|------|
| PC | フロー作成に使う Windows PC（デモも同じ PC） |
| PAD | Power Automate Desktop がインストール済みで、会社のアカウントでサインインしていること |
| ブラウザ | Microsoft Edge |
| PAD の Edge 拡張機能 | 「Microsoft Power Automate」拡張機能が Edge にインストール・**有効化**されていること（PAD の［ツール］→［ブラウザー拡張機能］→［Microsoft Edge］から入れられる） |

| ログイン | デモ用のダミー ID/PW（demo-user / demo-pass）。実在の認証情報ではない |

## 2. 貼り付け手順

1. PAD コンソールで［＋ 新しいフロー］を押し、フロー名に **申込状況チェック_デモ** と入力して［作成］を押す（PAD デザイナーが開く）。同じ名前の UI 要素が無い新しいフローにする。
2. [Main.txt](./Main.txt) をテキスト エディターで開き、**Ctrl＋A で全文をコピー**する。末尾の `# [ControlRepository][PowerAutomateDesktop]` の行とその後の JSON（最後の `}` まで）も必ず含める（UI 要素の定義。途中で切れると登録されない）。
3. PAD デザイナーの **Main** タブを開き、ワークスペースの空いている所を一度クリックしてから **Ctrl＋V** で貼り付ける。UI 要素は貼り付けだけで自動的に登録される。
4. 右側の［UI 要素］ペインで、画面が `LoginPage`・`ListPage`・`DetailPage` の3つ、要素が計8個（3・3・2）あること、`ListPage` の `detail-button` のセレクターが `button[data-action="detail"][data-application-no="%CurrentNo%"]` のまま（`%CurrentNo%` が残っている）であることを確かめる。
5. 変数ペインの **`LoginPassword` を機密としてマーク**（右クリック →［機密としてマーク］）し、［保存］を押す。アクション数は **128**、エラー ペインは 0 件になる。
6. エラー ペインに赤いエラーが出たら、該当のアクションを [reference.md](./reference.md) の「7. アクション表」の設定値どおりに直す。

- UI 要素が登録されない場合・貼り付けに失敗した場合は、[reference.md](./reference.md) の「3-1. 予備手順」（UI 要素を手で登録）と、アクション表からの手作業での作成に進む。
- 表の確認用 UI 要素表（U1〜U7・U22）、変数、アクション表は [reference.md](./reference.md)。

## 3. 実行手順

> **デモ当日の注意**
> 1. **【必須】実行中（Edge が閉じるまで）は、マウス・キーボードを操作しない。** ほかのウィンドウを前に出す操作もしない。通知を出すアプリ（チャット・メール等）は閉じておく。
> 2. **【推奨】念のため、実行前に（または［実行］を押した直後に）ほかのウィンドウ（PAD のデザイナー・コンソール、ターミナル、モックを起動したウィンドウ等）を最小化する。**
> 3. **止まったら、メッセージの文言を書き写すか、スクリーンショットを撮ってから［OK］を押す**（［OK］を押すと Edge が閉じてフローが終わり、文言は残らない）。そのあと、ほかのウィンドウを最小化して、もう一度実行する。
>
> 確認の範囲と経緯は [verification-log.md](./verification-log.md)。

1. リポジトリのルートで `node mock/server.js` を実行し、モックを起動する（ウィンドウは開いたままにする）。
2. 必要ならデモ用のデータを用意する：Edge で `http://localhost:8080/login.html` を開いて demo-user / demo-pass でログインし、一覧画面下部の「デモ操作」エリアで［新規案件を追加］（1件ずつ増える）や［初期データに戻す］→［実行する］（20件に戻る）を押す。**これは人が行う操作で、フローはデモ操作エリアを触らない。** 追加した案件も同じループで取得される。終わったらこの Edge のウィンドウは閉じてよい（フローは新しい Edge を起動する）。
3. PAD コンソールで「申込状況チェック_デモ」の［実行］（▷）を押す（デザイナーで開いている場合はデザイナーの［実行］でもよい）。押した後は、Edge が閉じるまで操作しない。
4. 新しい Edge が開き、ログイン → 一覧 → 先頭行から順に「詳細」→「一覧へ戻る」を全件くり返したあと、Edge が閉じる。実行時間は初期20件で約2分弱。
5. 出力ファイルを確認する。
   - 場所：**ドキュメント フォルダ\申込状況チェック_デモ**（エクスプローラーの左の［ドキュメント］から開く。OneDrive でドキュメントをバックアップしている PC では OneDrive 側のドキュメントになる）
   - ファイル：`申込状況_YYYYMMDD_HHMM.csv`（実行した日時。例：`申込状況_20261014_1030.csv`）と `latest.csv`。同じ分に2回実行すると履歴ファイルは上書きされる。`latest.csv` は毎回上書きされる
   - 中身：1行目が見出し（14列）、2行目から一覧の件数と同じ行数（初期データなら20行、1件追加後なら21行）。出力例は [reference.md](./reference.md) の「8. CSV 出力例」
6. **BOM（UTF-8 BOM 付き）の確認**：次のどちらかで確かめる。
   - Excel で `latest.csv` をダブルクリックして開き、日本語（お客さま名・申込種別など）が文字化けしていないこと
   - PowerShell で次を実行し、先頭3バイトが `EF BB BF` であること（ユーザー名を書かずにドキュメント フォルダを指定している）

     ```powershell
     Format-Hex -Path (Join-Path ([Environment]::GetFolderPath('MyDocuments')) '申込状況チェック_デモ\latest.csv') | Select-Object -First 1
     ```

**注意：供給地点特定番号（22桁）**
- CSV には22桁の数字をそのまま書き出す（人の決定事項。対策はしない）。
- Excel で CSV を開くと数値として扱われ、`9.9E+21` のような指数表示になり、下の桁が `0` に丸められて見える。**CSV ファイル自体の値は正しい**（メモ帳で開くと22桁のまま）。デモで Excel を見せる場合はこの点に注意する。

## 4. エラー早見表

どのエラーでも、フローはその場で止まり（CSV は書き出さない）、メッセージ「**申込状況チェック_デモ（エラーで停止しました）**」を表示する。メッセージの最初の部分が下の「どこで止まったか」に対応し、後ろの「（PAD のエラー情報：…）」に、止まったアクション名とエラー内容が出る。`<…>` は実行時の値。詳しい版（メッセージ全文・原因の見方）は [reference.md](./reference.md) の「6. エラー時のメッセージと対処」。

| どこで止まったか | 人がすること |
|------------------|--------------|
| E0：手順0（初期化。実行日時・作業フォルダー・データテーブル） | ドキュメント フォルダに `申込状況チェック_デモ` フォルダーを作れるか（同名のファイルが無いか、書き込み権限）を確認して再実行 |
| E1：手順1-1〜1-2（モック画面に接続できない） | `node mock/server.js` が起動しているか、`http://localhost:8080/login.html` を Edge で開けるか、PAD の Edge 拡張機能が有効かを確認して再実行 |
| E2：手順1-3〜1-4（ID・パスワードの入力、またはログインボタンのクリックができない） | Edge にログイン画面が表示されているか確認。ほかのウィンドウを最小化してから再実行し、実行中は操作しない |
| E3：手順1-4〜1-5（ログイン後に一覧画面が表示されない） | ほかのウィンドウを最小化してから再実行し、実行中は操作しない。それでも出る場合は、ID・パスワード（demo-user / demo-pass）と、一覧に「データを読み込めませんでした」が出ていないか、モックが止まっていないかを確認 |
| E4：手順2-1（一覧から申込番号を取得できない） | 一覧画面を確認して再実行（取得に使う JavaScript が [reference.md](./reference.md) の表のとおりか） |
| E5：手順2-2（一覧の件数表示「全 N 件」を取得できない） | 一覧の件数表示に「全 20 件」のように数字が出ているか確認して再実行 |
| E6：手順2-2（画面の件数と取得した申込番号の数が一致しない） | 実行中にデモ操作をしていないか確認。一覧を再読み込みして件数表示と行数が合っていることを確認して再実行 |
| E7：手順3-1（「詳細」ボタンをクリックできない） | 実行中に一覧のデータが変わっていないか確認して再実行 |
| E8：手順3-2（詳細画面が 30 秒以内に表示されない） | Edge に「該当する申込が見つかりません」が出ていれば、データが変わっていないか確認。Edge が一覧画面のままなら、ほかのウィンドウを最小化してから再実行し、実行中は操作しない |
| E9：手順3-3〜3-4（詳細画面から項目を取得できない） | PAD の Edge 拡張機能が有効か確認して再実行 |
| E10：手順3-3（申込番号が一致しない。対象と詳細画面で違う） | 別の行の「詳細」が押されていないか確認して再実行 |
| E11：手順3-4（14項目がそろわない） | モックの詳細画面が変わっていないか、データの値にカンマが入っていないか確認して再実行 |
| E12：手順3-5（一覧へ戻れない） | モックが止まっていないか確認。Edge が詳細画面のままなら、ほかのウィンドウを最小化してから再実行し、実行中は操作しない |
| E13：手順4（CSV を書き出せない） | `latest.csv` や履歴ファイルを Excel で開いていれば閉じて再実行 |

- 止まったときに、フローを自動で再実行はしない。人が原因を直してから、もう一度実行する。
- 手順3 の途中で止まった場合、それまでに取得した分も CSV には書き出さない（前回の `latest.csv` はそのまま残る）。
- ログインは最大3回まで自動でやり直す。3回とも一覧画面に進めないときだけ E2・E3 が出るが、そこまでメッセージが出ないので、Edge の画面が止まって見えても、メッセージが出るまで操作しない。

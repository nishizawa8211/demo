## 2. 準備

### 2-1. 新しいフローの作成
1. PAD コンソールで［＋ 新しいフロー］を押す。
2. フロー名に **申込状況チェック_デモ** と入力して［作成］を押す。PAD デザイナーが開く。

### 2-2. UI 要素（貼り付けで自動的に登録される）

`Main.txt` は UI 要素を `appmask['<画面名>']['<要素名>']` の名前で参照する。`Main.txt` の末尾（`# [ControlRepository][PowerAutomateDesktop]` の行とその後の JSON）に、下の表の **3画面・8要素（U1〜U7・U22）の定義** が入っている。PAD が UI 要素をコピーしたときに出力する形式と同じなので、**「3. 貼り付け手順」で全文を貼り付けるだけで UI 要素も登録される**（PAD 11.2609 の実機で確認済み〔10-0b〕。それでも登録されない場合は 3-1）。貼り付けの前に UI 要素を手で登録する必要はない。

- 下の表は **確認用**（貼り付け後に［UI 要素］ペインの内容と見比べる）。貼り付けで登録されない場合だけ、「3-1. 予備手順」で表のとおりに手で登録する。
- 画面名・要素名・セレクターは、大文字小文字・ハイフンまで表のとおり。`Main.txt` 末尾の定義では、どの要素も **カスタム セレクター 1つだけ**（表の「セレクター」列の文字列）になっている。
- 画面（`LoginPage` / `ListPage` / `DetailPage`）は、PAD が既定で作る「Edge のページ（`domcontainer`）」の形にしてある。URL では区別しないので、どの画面の要素も、そのとき Edge に表示されているページから探される。
- セレクターは `docs/screens.md` 1-1・S1〜S3 の業務用 `id` / `data-*` だけで書いてある（表示テキスト・行番号・クラス・階層位置・デモ操作エリアは使わない）。
- PAD のセレクター エディターで `#login-id` のような `#` の書き方が受け付けられない場合は、同じ意味の `input[Id="login-id"]`（要素名＋`Id` 属性）の形に書き換える（例は表の「`#` が使えない場合」列）。

**スクリーンショットの扱い**

- PAD がコピーするときは各画面・各要素の取り込み時のスクリーンショット（画像）が JSON に入るが、`Main.txt` には **実際の画面のスクリーンショットを入れていない**。代わりに、全画面・全要素で同じ **1×1 ピクセルの灰色のダミー画像**（PNG、69 バイト）を入れ、画像ファイルの保存場所（`ScreenshotPath`）は省いている。
- そのため、貼り付け後の［UI 要素］ペインで要素を選んでも **プレビュー画像は表示されない**（灰色の点になる）。セレクターで要素を探すので、フローの実行には影響しない。
- プレビュー画像が欲しい場合や、取り込みでスクリーンショットが必須と分かった場合（貼り付けで UI 要素が登録されない・画像のエラーが出る等）は、次のどちらかにする。
  - 「3-1. 予備手順」に進み、UI 要素を手で登録してから貼り付ける。
  - 貼り付けで登録された要素を［UI 要素］ペインで開き、取り込み直す（モックを表示した状態で要素を右クリック →［UI 要素の置換］等で同じ要素を Ctrl＋クリック）。取り込み直した後は、セレクターが表のセレクター1つだけになっているか必ず確かめる。

## 3. 貼り付け手順

1. 貼り付け先は、2-1 で作った **新しいフロー**（または ［UI 要素］ペインに `LoginPage`・`ListPage`・`DetailPage` と同じ名前の画面・要素が無いフロー）にする。同じ名前の UI 要素が既にあると、名前が重なって正しく登録されない場合がある。
2. [Main.txt](./Main.txt) をテキスト エディター（メモ帳等）で開き、**Ctrl＋A で全文を選択してコピー**する。**末尾の `# [ControlRepository][PowerAutomateDesktop]` の行と、その後の JSON（最後の `}` まで）も必ず含める**（この部分が UI 要素の定義。途中で切れると UI 要素が登録されない）。先頭の `#` コメント行も含めてよい。
3. PAD デザイナーで **Main** タブ（サブフロー）を開き、ワークスペースの空いている所を一度クリックしてから **Ctrl＋V** で貼り付ける。
4. 右側の **［UI 要素］ペイン** を開き、次を確かめる。
   - 画面が `LoginPage`・`ListPage`・`DetailPage` の **3つ** あり、その下に要素が **計8個**（`LoginPage` 3個・`ListPage` 3個・`DetailPage` 2個）できていること。名前が 2-2 の UI 要素表と同じであること。
   - **U6（`ListPage` の `detail-button`）をダブルクリック** してセレクター ビルダーを開き、カスタム セレクターが `button[data-action="detail"][data-application-no="%CurrentNo%"]` のまま（`%CurrentNo%` が残っている）であること。
   - 何個か（例：U1 `login-id`・U4 `application-table-loaded`）を開き、セレクターが表の「セレクター」列と同じ1つだけであること。
5. 変数ペインに `StepMessage`・`BaseUrl`・`CurrentTable` などの変数ができていること、アクションが「7. アクション表」と同じ順に並んでいることを確かめる（表の No.1〜3 のように、ブロックの開始とそのエラー時の設定は PAD 上では1つのアクションとして表示される。No.106〜107 も同様）。PAD のステータス バーの表示は、04b の版（表 84 行）で **96 アクション**、04c の `1f6091f` の版（表 98 行）で **113 アクション**（実機で確認。PAD の構文解析器で数えた 113 と一致）だった（PAD はコメントも1アクションとして数え、ブロックのエラー時の設定は開始と1つにまとめ、If・Loop の終わり（End）も1つと数えるため、表の行数とは数え方が違う）。`93c7226` の版（表 92 行）は **109 アクション**（実機で確認。構文解析器で数えた 109 と一致：10-0f）。`f8d3b85` の版（表 90 行）は **108 アクション**（実機で確認。構文解析器で数えた 108 と一致：10-0g）。04d の1回目の版（`5ebeec4`、表 103 行）は **126 アクション**（実機で確認。構文解析器で数えた 126 と一致：10-0h）。**今の版（04d の差し戻し1回目の修正 `12be3e2`、表 107 行）は 128 アクション**（実機で確認。構文解析器で数えた 128 と一致。増えたのは「ウィンドウにフォーカスする」2つで、直後の個別のエラー時の設定は PAD では1つにまとめて数える：10-0・10-0i）。
6. 「4. 変数設定」の **`LoginPassword` を機密としてマーク** する。
7. デザイナー上部の［保存］を押す。
8. エラー ペインに赤いエラーが出ている場合は、該当のアクションをダブルクリックし、「7. アクション表」の設定値どおりに直す（UI 要素名の誤り・列挙値の名前の違いが多い）。

- **UI 要素が登録されない・UI 要素の部分でエラーになる場合**：貼り付けた分を削除し、「3-1. 予備手順」で UI 要素を手で登録してから、もう一度貼り付ける。
- **貼り付けに失敗した場合**（何も貼り付けられない、エラーが多くて直せない等）：貼り付けた分を削除し、「3-1. 予備手順」で UI 要素を登録したうえで、**「7. アクション表」を No.1 から順に見て、同じアクションを左のアクション一覧からドラッグして手作業で作る**。表の「主な設定値」「生成される変数」「エラー時の設定」をそのまま入力すれば、`Main.txt` と同じフローになる。

- 「ブロック エラー発生時」（BLOCK）は、ブロックの中にアクションを入れる入れ物になる。表で「ブロック内」と書いたアクションは、そのブロックの中に入れる。
- ブロックのエラー時の設定（No.2〜3 など）：ブロックのアクションを開き →［例外処理モード］（または［エラー発生時］）で **［フロー実行を続行する］→［ラベルに移動］→ `ErrorEnd`** を選ぶ。ラベル `ErrorEnd`（No.102）は先に作っておくと選べる。

### 3-1. 予備手順：UI 要素を手で登録する（貼り付けで UI 要素が登録されない場合だけ）

通常は不要。貼り付けで UI 要素が登録されない・エラーになる場合に、**2-2 の UI 要素表と同じ画面名・要素名・セレクターで UI 要素を手で登録してから**、アクションを貼り付ける（またはアクション表から手作業で作る）。

**登録のしかた（1要素ごと）**
1. `node mock/server.js` でモックを起動し、Edge で対象の画面を開いておく（一覧・詳細はログインしてから開く。開く画面は表の「画面（取り込むとき開く画面）」列）。
2. PAD デザイナー右側の［UI 要素］ペイン →［UI 要素の追加］を押す。
3. Edge 上で対象の要素にマウスを合わせ、赤枠が出たら **Ctrl＋クリック** で取り込む。
4. 取り込まれた画面（`Web Page '...'` のような名前）を右クリック →［名前の変更］で、表の「画面名」（`LoginPage` / `ListPage` / `DetailPage`）にする。2個目以降の同じ画面の要素は、この画面の下に入る。
5. 取り込まれた要素を右クリック →［名前の変更］で、表の「要素名」にする。
6. 要素をダブルクリックしてセレクター ビルダーを開き、**［テキスト エディター］をオンにする**。
7. 自動生成されたセレクター（`html > body > main > ...` のような階層位置や `:eq()`・クラスを含むもの）を **全部消し**、表の「セレクター」をそのまま貼り付けて［保存］する。
8. セレクターが複数登録されている場合（セレクター一覧に2つ以上ある場合）は、表のセレクター1つだけを残して他は削除する。

**登録した後のアクションの貼り付け**
- 8個すべて登録したら、[Main.txt](./Main.txt) のうち **`# [ControlRepository][PowerAutomateDesktop]` の行より前だけ** をコピーして Main に貼り付ける（末尾の JSON まで貼ると、同じ名前の UI 要素がもう一度登録されようとして重なる）。その後は「3. 貼り付け手順」の 5. 以降と同じ。
- それでも貼り付けられない場合は、「7. アクション表」から手作業で作る（上の「貼り付けに失敗した場合」）。

## 6. エラー時のメッセージと対処

どのエラーでも、フローは **その場で止まり（CSV は書き出さない）**、次のメッセージを表示する。メッセージの［OK］を押すと、ブラウザを閉じる処理を試みてフローが終わる（ブラウザが起動していない場合は閉じる処理を飛ばす）。

- メッセージ画面のタイトル：**申込状況チェック_デモ（エラーで停止しました）**
- 手順ごとにブロック（「ブロック エラー発生時」）を分け、エラーになったらラベル `ErrorEnd` に移動してメッセージを表示する。メッセージ文言は変数 `StepMessage` に、その手順を始める前に入れてある。
- `<申込番号>`・`<件数>` などは実行時の値が入る。
- **今の版では、表の文言の後ろに「（PAD のエラー情報：…）」が付く**（No.103〜105。10-0e。実機で表示を確認：10-0g）。中身は PAD が記録した最後のエラーで、「サブフロー: main、アクション: <番号>、アクション名: <アクション名>」と「エラー メッセージ: <PAD のエラーの内容>」（後ろに「追加情報: …」が付くことがある）。**どの手順で止まったかは表の文言（`StepMessage`）で、どのアクションで・どんなエラーかは「PAD のエラー情報」で分かる**。アクションの番号は PAD デザイナーの左に出る番号（コメントも1つと数える）で、下の「7. アクション表」の No とは違う（アクション名で表と突き合わせる。2026-10-19 の `f8d3b85` の実機では、アクション 47 がログインボタンのクリック〔今の版の No.42〕、アクション 28 がログイン画面の待機〔No.23〕だった。04d では手順1 のアクションが増えたので、ログインボタンのクリックより後のアクションの番号は `f8d3b85` と違う。04d の `5ebeec4` の実機では、アクション 90 が手順3-2 の詳細画面の待機〔今の版の No.78〕だった。今の版では手順3 に前面に出す処理を2つ足したので、「詳細」ボタンのクリックより後のアクションの番号は `5ebeec4` とも違う〔詳細画面の待機は 91、の見込み〕）。アクション名は PAD の表示（例：「Web ページのリンクをクリック」）で、表の名前（「…クリックします」）と少し違う場合がある。
  - 実機で出た例（2026-10-19、`f8d3b85` の版）：E1 の例「手順1-1〜1-2：モック画面に接続できません。server.js が起動しているか確認してください（PAD のエラー情報：サブフロー: main、アクション: 28、アクション名: Web ページのコンテンツを待機　エラー メッセージ: タイムアウトの期限が切れています。　追加情報: {}）」。E2 の例「手順1-3〜1-4：ログイン画面で ID・パスワードの入力またはログインボタンのクリックができませんでした（PAD のエラー情報：サブフロー: main、アクション: 47、アクション名: Web ページのリンクをクリック　エラー メッセージ: セレクター #login-button を含む要素が見つかりません。.）」（この E2 は、今の版ではログインボタンのクリックをやり直すので、この形では出ない。下の表の E2・E3 を参照）
  - 止まったときは、**メッセージの文言をそのまま書き写すか、スクリーンショットを撮ってから［OK］を押す**（［OK］を押すとブラウザーが閉じてフローが終わり、文言は残らない）。
  - エラー メッセージの中のファイルのパスに、ユーザー名を含む部分（`<ドライブ>:\Users\<名前>\…`）があれば、作業フォルダ名（`申込状況チェック_デモ`）の前まで、またはその行の終わりまでを `<ユーザー フォルダー>` に置き換えて表示する（No.104）。
  - 「テキストを置換する」には、PAD の決まりで **個別のエラー時の設定（失敗しても続ける設定）を付けられない**（10-0f）。そのため、万一この置き換え自体が失敗すると、メッセージは出ずに PAD の実行エラーとしてその場で止まる（ブラウザーは開いたまま残る）。正規表現は固定の文字で、置き換える元（`%LastError%`）は必ずテキストになる（エラーが無ければ「エラーはありません」）ので、失敗する場面は想定していない。`93c7226` の版までの「失敗したら（取得できませんでした）と表示する」仕組みは、この理由でなくした。
  - 条件の確認で止めた場合（E2・E3 の3回失敗・E6・E10・E11）は、PAD のアクション自体はエラーになっていないので、「PAD のエラー情報」は「エラーはありません」か、それより前に記録されたエラー（例：ログインのやり直しで、止めずに続けた前面に出す処理・入力・クリック・一覧の待機のエラーや、手順3 で止めずに続けた前面に出す処理〔No.74・90〕のエラー）になる。その場合も、止まった理由は表の文言で分かる。ログインのやり直しで3回とも失敗したときは、PAD のエラー情報が最後に失敗したアクション（例：「Web ページのリンクをクリック」の「セレクター #login-button を含む要素が見つかりません。」、「Web ページのコンテンツを待機」の「タイムアウトの期限が切れています。」）を示す手がかりになる。

**`Main.txt` を手で直すときの注意（文字のエスケープ）**

PAD の貼り付けテキストでは `$'''…'''` の中の次の文字をエスケープする。デザイナーの画面には下の「設定値」の形（`\` や `"` が1つ）で表示されるので、表の値をそのまま `Main.txt` に書くと貼り付け時に構文エラーになる。

| `\`（円記号・バックスラッシュ） | `\\` | No.13（`%DocumentsFolder%\\%WorkFolderName%`）・No.98・99（CSV のファイル パス）・No.104（正規表現。画面での `\\Users\\` は `Main.txt` では `\\\\Users\\\\`） |

**CSV の設定（No.98・99）について**

- 列区切り記号：**コンマ**を明示して選ぶ（「システムの既定」は選ばない。地域設定によって区切りが変わるのを避けるため）。
- 列名を含める：オン（1行目が見出しになる）。ファイルが存在する場合：上書き。
- CSV の書き出しは手順3 の全件ループが最後まで終わった後だけ実行される。手順0〜3 のどこかでエラーになると、ラベル `ErrorEnd` に移動するため No.98・99 は実行されない。

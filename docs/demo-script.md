## 構成の方針（人の決定 2026-10-20）

- **本編**：スプリント04d（ログイン〜CSV 出力）までで完結する。ログイン → 一覧 → 詳細 → CSV 出力を Power Automate Desktop（PAD）で自動化できることを見せる。
- **付加価値パート（任意）**：SharePoint 保存・前回比較・Teams 投稿・新規案件の検知（スプリント05）。**05 が完成し、事前確認で動作が安定しているときのみ実施**する。未完成・不安定なら実施せず、本編だけで終える。
- 本編の台本・準備は、付加価値パートの有無に依存しない。

## 2. 本編（約10分。スプリント04d の範囲で完結）

### シーン1. 導入（約1分）

| 誰が   | 何をする   | 何が見える                             |
| ------ | ---------- | -------------------------------------- |
| 説明者 | 口頭で説明 | （タイトル画面または申込一覧のモック） |

**話すポイント**

- 申し込み状況は送配電側のシステムで、一覧 → 各案件の詳細を開いて確認している。
- 一括ダウンロード機能がないため、今は RPA で詳細を順に開いて CSV に書き出している。
- 今日は「同じことを Power Automate でもできる」ところをお見せする。
- 画面は送配電側システムを模した **架空のモック**、データもすべて架空であることを最初に伝える。

### シーン2. モック画面の紹介（約2分）

| 誰が   | 何をする                                        | 何が見える                                                         |
| ------ | ----------------------------------------------- | ------------------------------------------------------------------ |
| 操作者 | ログイン画面でダミー ID/PW を入力し「ログイン」 | 申込一覧（全 20 件）                                               |
| 操作者 | 任意の行の「詳細」を押す                        | 申込詳細（需要場所住所・希望日・工事予定日・送配電受付番号・備考） |
| 操作者 | 「一覧へ戻る」、続けて「ログアウト」            | 申込一覧 → ログイン画面                                            |

**話すポイント**

- 一覧には概要だけ、詳しい情報は1件ずつ詳細を開かないと見られない。これを人や RPA が順番に開いている。

### シーン3. フロー実行（約3〜4分）

| 誰が     | 何をする                                  | 何が見える                          |
| -------- | ----------------------------------------- | ----------------------------------- |
| 操作者   | PAD コンソールでフローを実行              | Edge が新しく起動し、自動でログイン |
| （自動） | 一覧 → 詳細 → 一覧に戻る を20件分繰り返す | 詳細画面が次々に切り替わる          |
| （自動） | CSV 作成（ローカルの作業フォルダ）        | Edge が閉じ、PAD のフローが完了表示 |

**話すポイント**

- 人が操作しているのと同じ画面操作を、Power Automate Desktop が行っている（今の RPA と同じこと）。
- 待っている間に：画面の項目を取得して、1件1行の CSV にまとめている。
- 定期実行にすれば、決まった時間に自動で実行できる（本デモは手動実行）。※定期実行の可否は今回の範囲外のため、断定しない。

| 操作者 | CSV を Excel（またはプレビュー）で開く           | 20件 × 14項目。文字化けなし                               |

**話すポイント**

- 一覧には無い詳細項目（住所・工事予定日・備考など）まで含めて、全件が1つのファイルにまとまる。
- 一括ダウンロード機能がなくても、一覧化はこの仕組みで実現できる（伝えたいこと①）。

### シーン5. 本編のまとめ（約1〜2分）

| 誰が   | 何をする     | 何が見える       |
| ------ | ------------ | ---------------- |
| 説明者 | 口頭でまとめ | CSV の画面のまま |

**話すポイント**

- 今の RPA と同じ「ログイン → 一覧 → 詳細 → CSV」を、Power Automate Desktop でも実現できる（伝えたいこと①）。

- この先は、保存先の共有や新規案件の通知などに広げることも検討できる（実施の可否は断定せず、次の段階の話として触れる）。

## 3. 付加価値パート（任意。05 完成時のみ実施。約8分）

> 本編のシーン5のあとに続けて実施する。実施するときは、シーン5の「広げることも検討できる」を受けて「実際にその例をお見せします」とつなぐ。使うフローは資産5（`flows/application-check-notify/`）。

### シーンA1. 新規案件が登録された状況を作る（約1分）

| 誰が   | 何をする                                                                  | 何が見える                                                                                         |
| ------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 操作者 | ログインし、一覧画面を下までスクロールして「新規案件を追加」を2回押す     | 「DM-2026-0021 を追加しました」→「DM-2026-0022 を追加しました」、一覧の先頭に2件が増え「全 22 件」 |
| 操作者 | 一覧画面の「ログアウト」                                                  | ログイン画面                                                                                       |

**話すポイント**

- 「送配電側で新しい申し込みが2件登録された」という想定。画面下部のデモ操作エリアはデモ用の仕掛けで、実際のシステムには無い。
- 一覧を見ても、どれが新しく増えた案件かは目印が無いのでわからない。誰もまだこの2件に気づいていない状態。

### シーンA2. フロー実行（約3分）

| 誰が     | 何をする                                        | 何が見える                          |
| -------- | ----------------------------------------------- | ----------------------------------- |
| 操作者   | PAD コンソールで資産5のフローを実行             | Edge が新しく起動し、自動でログイン |
| （自動） | 一覧 → 詳細 → 一覧に戻る を22件分繰り返す       | 詳細画面が次々に切り替わる          |
| （自動） | CSV 作成・SharePoint 保存・前回比較・Teams 投稿 | Edge が閉じ、PAD のフローが完了表示 |

**話すポイント**

- 待っている間に：取得した情報は CSV にまとめ、前回の CSV と申込番号で比べて「新しく増えた案件」だけを取り出している。

### シーンA3. 結果の確認（約3分）

| 誰が   | 何をする                                         | 何が見える                                                                                                  |
| ------ | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 操作者 | Teams の個人チャットを表示                       | 「新規案件が 2 件あります」の投稿。2件の申込番号・お客さま名・申込種別・容量（変更前 → 変更後）・ステータス |
| 操作者 | 投稿内の CSV リンクを開く                        | SharePoint 上の `申込状況_YYYYMMDD_HHMM.csv`                                                                |
| 操作者 | CSV を Excel（またはブラウザのプレビュー）で開く | 22件 × 14項目。文字化けなし                                                                                 |
| 操作者 | SharePoint の保存先フォルダを表示                | 日時付きの履歴ファイルと `latest.csv`                                                                       |

**話すポイント**

- 新規案件が Teams に自動で届くので、確認漏れを防げる（伝えたいこと②）。
- CSV は全項目入りで SharePoint に残るので、担当者個人ではなくチーム全体で同じ情報を見られる（伝えたいこと③）。

### シーンA5. 全体のまとめ（約1分）

## 4. うまくいかないとき

| 症状                                 | その場の対応                                                                                                                      |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| フローが途中で止まりメッセージが出た | メッセージの内容を読み上げず、事前に用意した正常時のスクリーンショット（録画）で続ける。デモ後に原因確認                          |
| モックが表示されない                 | `server.js` を起動し直し、一覧画面で件数を確認してから再実行                                                                      |
| 【付加価値】Teams に投稿が来ない     | 数十秒待つ。来なければ SharePoint の CSV を見せて、通知部分はスクリーンショットで説明                                             |
| 【付加価値】新規件数が想定と違う     | 付加価値の準備 A1（初期データに戻す）か A2（フローの1回実行）が漏れている可能性。時間があればリセットからやり直す                 |
| 【付加価値】パート全体が不安定       | 付加価値パートは実施せず、本編のまとめ（シーン5）で終了する。実施済みシーンの結果は無理に見せない                                |

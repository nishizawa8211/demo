## 0. 概要

| 項目       | 内容                                                                                                                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 伝えること | ① 一括ダウンロード機能がなくても、申し込み状況を自動で一覧化（CSV 化）できる ② 新規案件が Teams に自動で通知され、確認漏れを防げる ③ 担当者ごとの個別管理から、チーム全体で共有できる形に変えられる |
| 伝え方の軸 | 「**今の RPA と同じこと（ログイン → 一覧 → 詳細 → CSV）を Power Automate でもでき、そのうえ新規案件を通知できる**」                                                                                 |
| 所要時間   | 本編 約12分＋任意シーン 約3分（合計 約15分）【要確認：持ち時間】                                                                                                                                    |
| 役割       | **説明者**（話す人）と **操作者**（PC を操作する人）。1人で兼ねてもよい【要確認】                                                                                                                   |
| 使う PC    | フロー作成に使っている PC（brief 9）                                                                                                                                                                |
| 画面の配置 | 画面共有するのは「Edge（モック）」「PAD コンソール」「Teams（作成者の個人チャット）」「SharePoint（CSV 保存先）」の4つ。事前にタブ・ウィンドウを開いておく                                          |

## 1. 事前準備（デモ前日〜直前）

### 1-1. 前日まで

| #   | 作業                                                                                                                  | 確認すること           |
| --- | --------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | PAD に会社のアカウントでサインインし、Teams・SharePoint の接続が有効か確認                                            | 接続にエラー表示が無い |

### 1-2. 直前のリセット手順（所要 約5分）

モックからは SharePoint を操作できないため、**モックを初期20件に戻したあと、フローを1回実行して `latest.csv` を初期20件の内容で作り直す**。

| #   | 操作者がすること                                                                                                                                                             | 見えること                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 1   | `server.js` を起動する                                                                                                                                                       | コンソールに起動メッセージ                       |
| 2   | Edge で `http://localhost:8080/login.html` を開き、ダミー ID/PW でログイン                                                                                                   | 申込一覧                                         |
| 3   | 一覧画面下部のデモ操作エリアで「初期データに戻す」を押し、確認表示で「実行する」                                                                                             | 「初期データ（20件）に戻しました」・「全 20 件」 |
| 4   | PAD コンソールでフロー「申込状況チェック\_デモ」を1回実行する                                                                                                                | フローが完了する                                 |
| 5   | SharePoint の保存先で `latest.csv` を開き、20件であることを確認する                                                                                                          | `latest.csv` が初期20件                          |
| 6   | Teams の個人チャットを確認する。手順4の実行で「新規案件はありません」が投稿される（`latest.csv` が無かった場合は投稿なし）。本番の投稿と混同しない位置までスクロールしておく | 最新位置が表示されている                         |
| 7   | （任意）リハーサル・手順4で作られた履歴ファイル `申込状況_*.csv` を別フォルダへ移す                                                                                          | 保存先が見やすい                                 |
| 8   | Edge でログイン画面（`/login.html`）を開いておく                                                                                                                             | ログイン画面が表示                               |
| 9   | PAD コンソールでフローを選べる状態にする                                                                                                                                     | フロー一覧に表示                                 |

- 手順4の時点でモックが20件より多い（「初期データに戻す」を押し忘れた）と、`latest.csv` に追加分が入り、本番で新規として出なくなる。手順3の「全 20 件」を必ず確認する。

- PC の通知（メール・チャットのポップアップ）をオフにする。画面共有に秘密情報（URL・アカウント名など）が映らないよう、不要なタブ・ウィンドウは閉じる。

## 2. 本編

### シーン1. 導入（約1分）

| 誰が   | 何をする   | 何が見える                             |
| ------ | ---------- | -------------------------------------- |
| 説明者 | 口頭で説明 | （タイトル画面または申込一覧のモック） |

**話すポイント**

- 申し込み状況は送配電側のシステムで、一覧 → 各案件の詳細を開いて確認している。
- 一括ダウンロード機能がないため、今は RPA で詳細を順に開いて CSV に書き出し、新規案件がないかを確認している。
- 今日は「同じことを Power Automate でもでき、そのうえ新規案件を Teams に通知できる」ところをお見せする。
- 画面は送配電側システムを模した **架空のモック**、データもすべて架空であることを最初に伝える。

### シーン2. モック画面の紹介（約2分）

| 誰が   | 何をする                                        | 何が見える                                                         |
| ------ | ----------------------------------------------- | ------------------------------------------------------------------ |
| 操作者 | ログイン画面でダミー ID/PW を入力し「ログイン」 | 申込一覧（全 20 件）                                               |
| 操作者 | 任意の行の「詳細」を押す                        | 申込詳細（需要場所住所・希望日・工事予定日・送配電受付番号・備考） |
| 操作者 | 「一覧へ戻る」                                  | 申込一覧                                                           |

**話すポイント**

- 一覧には概要だけ、詳しい情報は1件ずつ詳細を開かないと見られない。これを人や RPA が順番に開いている。

### シーン3. 新規案件が登録された状況を作る（約1分）

| 誰が   | 何をする                                                                  | 何が見える                                                                                         |
| ------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 操作者 | 一覧画面を下までスクロールし、デモ操作エリアの「新規案件を追加」を2回押す | 「DM-2026-0021 を追加しました」→「DM-2026-0022 を追加しました」、一覧の先頭に2件が増え「全 22 件」 |
| 操作者 | 一覧画面の「ログアウト」                                                  | ログイン画面                                                                                       |

**話すポイント**

- 「送配電側で新しい申し込みが2件登録された」という想定。画面下部のデモ操作エリアはデモ用の仕掛けで、実際のシステムには無い。
- 一覧を見ても、どれが新しく増えた案件かは目印が無いのでわからない。誰もまだこの2件に気づいていない状態。

### シーン4. フロー実行（約3〜4分）

| 誰が     | 何をする                                        | 何が見える                          |
| -------- | ----------------------------------------------- | ----------------------------------- |
| 操作者   | PAD コンソールでフローを実行                    | Edge が新しく起動し、自動でログイン |
| （自動） | 一覧 → 詳細 → 一覧に戻る を22件分繰り返す       | 詳細画面が次々に切り替わる          |
| （自動） | CSV 作成・SharePoint 保存・前回比較・Teams 投稿 | Edge が閉じ、PAD のフローが完了表示 |

**話すポイント**

- 人が操作しているのと同じ画面操作を、Power Automate Desktop が行っている（今の RPA と同じこと）。
- 待っている間に：取得した情報は CSV にまとめ、前回の CSV と申込番号で比べて「新しく増えた案件」だけを取り出している。
- 定期実行にすれば、毎朝などの決まった時間に自動で確認できる（本デモは手動実行）。※定期実行の可否は今回の範囲外のため、断定しない。

### シーン5. 結果の確認（約3分）

| 誰が   | 何をする                                         | 何が見える                                                                                                  |
| ------ | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 操作者 | Teams の個人チャットを表示                       | 「新規案件が 2 件あります」の投稿。2件の申込番号・お客さま名・申込種別・容量（変更前 → 変更後）・ステータス |
| 操作者 | 投稿内の CSV リンクを開く                        | SharePoint 上の `申込状況_YYYYMMDD_HHMM.csv`                                                                |
| 操作者 | CSV を Excel（またはブラウザのプレビュー）で開く | 22件 × 14項目。文字化けなし                                                                                 |
| 操作者 | SharePoint の保存先フォルダを表示                | 日時付きの履歴ファイルと `latest.csv`                                                                       |

**話すポイント**

- 新規案件が Teams に自動で届くので、確認漏れを防げる（伝えたいこと②）。
- CSV は全項目入りで SharePoint に残るので、担当者個人ではなくチーム全体で同じ情報を見られる（伝えたいこと③）。
- 一括ダウンロード機能がなくても、一覧化はこの仕組みで実現できる（伝えたいこと①）。

### シーン6（任意）. 新規が無いときの動き（約3分）

## 3. うまくいかないとき

| 症状                                 | その場の対応                                                                                                           |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| フローが途中で止まりメッセージが出た | メッセージの内容を読み上げず、事前に用意した正常時のスクリーンショット（録画）で続ける。デモ後に原因確認               |
| モックが表示されない                 | `server.js` を起動し直し、一覧画面で件数を確認してから再実行                                                           |
| Teams に投稿が来ない                 | 数十秒待つ。来なければ SharePoint の CSV を見せて、通知部分はスクリーンショットで説明                                  |
| 新規件数が想定と違う                 | リセット手順（1-2）の 3（初期データに戻す）か 4（フローの1回実行）が漏れている可能性。時間があればリセットからやり直す |
